# Recovery repeats only recorded token-budget failures under a new policy

**Scope:** User-authorized GPT-OSS truncation recovery, not a replacement full baseline or an eligible homogeneous research cohort. Preserve original2012-row parent unchanged. Main implements `scripts/recover_stance_baseline_truncations.py` and tests; code-reviewer and spec-reviewer must approve before dispatch.

## The parent fixes the recovery denominator

Load the full approved input pack and complete parent with LC0. Select exactly sorted parent keys whose generation failure_type is truncated and finish_reason token_budget; no ticker override or arbitrary cohort input. Include both role and original row hashes via parent content identity. Original valid rows and other failure causes are not retried. New max_new_tokens must be a genuine integer strictly greater than old budget. Keep channel, cache, pad/stops, dtype, wrapper/schema/template, checkpoint metadata files identical to parent; resolved checkpoint path and actual GPU/backend may differ and must be recorded as recovery provenance. Parent checkpoint metadata digest comparison must use the parent's exact file dictionary; directory copy and source weight-byte hashes are separately verified before submission. The accepted tokenizer identity includes name_or_path. For verified relocation only, require the loaded tokenizer name equals the actual resolved checkpoint path, set its logical name_or_path to the parent's recorded resolved path before compiling, record both actual/logical names in tokenizer_relocation provenance, and still require the complete tokenizer hash to match. Do not drop the name from the accepted identity or skip hash comparison.

New CLI arguments: --inputs --parent --model --output-dir required; --max-new-tokens default4096; --timeout-seconds default1200. New timeout is explicit to allow longer decoding, not described as unchanged policy. No device/host identity equality claim; actual model/backend/code records use existing `runtime_metadata` plus recovery script's own SHA. Native precision and all grammar controls inherited from parent. Actual tokenizer/head/schema/stops/grammar identities must match reference parent provenance, ignoring mask_backend/model_binding and changed policy/budget. Actual wrapper equality checked on first and every retry prompt. Native Harmony prompt boundary and driver preserved, no channel stripping/forced headers.

## Recovery outputs remain independent and write-once

Root has registration.json, store.lock, records/, summary.json on completion. Nonblocking exclusive persistent flock guards one writer; exclusive fresh directory initializes; existing partial layout rejects. Canonical registration binds complete parent content/plan hash, selected full keys, old and new policy, exact model/runtime/source metadata and research_eligible=false. Resume requires byte-identical registration; validates every existing record before skipping, including unsuccessful retry outputs. Records named keySHA.json bind key, parent content hash and original generated token hash, full retry generation and issuer outcome. Publish canonical record via fsynced staging file + hard link no-overwrite + unlink + directory fsync; interruption leftovers explicitly reject (no silent discard), after uncertain publication abort. Summary generated only with exact selected-key coverage, records old/retry failure counts and decisions and explicitly marks adaptive budget selection, mixed policies if joined to original, research_eligible=false. Do not mutate parent or treat recovery as original-policy completion. An empty truncation set may produce complete empty recovery without loading a checkpoint.
