# Lossless tokenizer adapters must precede checkpoint eligibility

**Goal:** Extend the accepted plain-JSON capability to a narrowly tested Gemma-style byte-fallback decoder and recognize declared backend special tokens without weakening UTF-8, factory identity or model binding. This is an engineering slice, not a formal model protocol or four-checkpoint certification.

## 1. Grounding and boundaries

Verified in `llm_bias/core/inference/structured_output.py:compile_decision_grammar`: stop membership uses `tokenizer.all_special_ids`; `_lossless_vocab` accepts only HF fast BPE, plain ByteLevel, xgrammar BYTE_LEVEL and no prefix adjustment. `_bind_model` checks available declarations before forward; `generate_structured_decision` records a fixed ByteLevel byte-policy string and requires strict concatenated-byte/HF decode equality.

Read-only remote reconnaissance reported Gemma BPE decoder `Sequence([Replace('▁',' '), ByteFallback, Fuse])`, xgrammar BYTE_FALLBACK, and matching vocabulary bytes. It also reported GLM backend-added `special:true` IDs missing from named HF special IDs. These reports motivate synthetic tests, not a claim that generation passed. The reconnaissance's channel-start observations and proposed stop-binding relaxation are **not accepted evidence** here.

In scope: lossless decoder validation, explicit byte-policy provenance, complete special-token membership and checkpoint-free regression tests. Non-goals: channel drivers, Harmony header injection, channel stripping, changing `_bind_model` stop agreement, weakening schema/grammar validation, changing compiler inputs or historical runs, weights/GPU/downloads, new packages, normalization/template mutation. Unsupported decoders remain unsupported. No generic decoder interpreter.

## 2. Numbered contracts (new design unless marked verified)

**REQ-T1 — Admit exactly one additional decoder pipeline.** Keep current ByteLevel behavior. The new family requires `PreTrainedTokenizerFast`, backend model BPE, xgrammar `VocabType.BYTE_FALLBACK`, `info.add_prefix_space == False`, and exactly three decoder entries in order: Replace with literal String pattern `▁` and content `' '`, ByteFallback, Fuse. Reject regex replacement, extra/reordered decoder stages, Strip/Metaspace, Unigram, RAW, prefix-space adjustment and malformed serialized descriptors. Validate complete native decoder descriptors rather than a loose substring test. A pre-tokenizer/normalizer must not be rewritten to obtain acceptance. Unknown configurations fail explicitly with `UnsupportedTokenizerError` before generation.

**REQ-T2 — Verify exact token bytes.** For this supported pipeline, reconstruct an ordinary token matching the native ByteFallback byte-token syntax as one byte; otherwise replace each literal `▁` with a space and UTF-8 encode. Establish the precise case-sensitive byte syntax using installed tokenizers tests; do not accept extra forms merely because a broad regex matches. Backend added-token records require separate scrutiny: literal added-token contents must decode literally, not inherit ordinary vocabulary byte/space interpretation. Compare every known token's reconstructed bytes to `info.decoded_vocab[token_id]`. Any disagreement is blocked (as existing ByteLevel mismatch handling does); if a configured stop disagrees, compilation fails. Check padded IDs and genuine literal U+FFFD. Runtime strict UTF-8 concatenation and HF decode equality remain mandatory; split multibyte tokens are valid only when the final concatenation is valid. Incomplete/invalid byte sequences cannot become primary-valid through replacement decoding. Handle backend NUL truncation by blocking disagreements, not laundering them.

**REQ-T3 — Persist adapter identity defensively.** Add explicit byte policy to the factory-owned capability identity: `hf-fast-bpe-bytelevel-strict-utf8-v1` or `hf-fast-bpe-bytefallback-strict-utf8-v1`. Result provenance derives it from the bound capability, never a caller string or model slug. Keep actual grammar/tokenizer-info and capability registry checks, immutable result exports, exact schema bytes, pinned grammar correction, root-failure preservation and model/head/stop binding intact. Add a defaulted field only if old construction compatibility requires it; a copied or modified capability must still be rejected. No activation arrays are retained.

**REQ-T4 — Recognize backend-declared specials without allowing ordinary stops.** Build a validated union of named HF special IDs and `special:true` records in the fast-tokenizer backend `added_tokens` list. Each backend record must have a genuine nonbool integer ID matching tokenizer vocabulary content/ID and inside head range; malformed/conflicting declarations fail rather than coerce. The same union feeds stop membership, blocked special IDs, factory identity and continuation rejection. Non-stop added channel tokens remain blocked even when absent from HF named specials. Ordinary tokens and padded IDs remain invalid stops. Do not change available model-config stop checks or allow trusted binding to override contradictions.

## 3. Slice T1 is independently testable

Files: modify only `llm_bias/core/inference/structured_output.py`; create `tests/test_stance_tokenizer_adapters.py`. Existing tests may be changed only when their asserted unsupported decoder is precisely the newly admitted full pipeline; the existing rejection of standalone ByteFallback and Sequence(ByteLevel) remains correct.

Consumes verified `compile_decision_grammar`, `generate_structured_decision`, `VerifiedModelBinding`, strict parser and factory capability APIs in `structured_output.py`. Produces the extended compiler with unchanged public compile/generate signatures and explicit provenance policy. No model-family auto-selection.

Fixture: synthetic HF fast BPE tokenizer with all 256 native byte fallback entries, `▁` ordinary tokens, valid/malformed byte spellings and UTF-8 pieces, literal added-token contents including special/channel/stop tokens. Use actual tokenizers decoder and installed xgrammar, not a fake mapping that restates the reconstruction. Tiny HF CPU model or existing fake generation harness exercises legal JSON for buy/sell, Unicode reason, exact-budget completion and invalid-byte output. Hand-check decoding at token boundaries, added-token boundaries and mixed ordinary/byte sequences. Model-declared stops must agree in these fixtures.

Red phase: reproduce unsupported full pipeline and missing-backend-special stop failure against current code; assert old plain ByteLevel success and unsupported variants. Green phase: implement the narrow adapter/special union, show strict invalid UTF-8 and surrogate handling still fail closed, capability/provenance mutation fails, non-stop backend specials cannot become JSON payload. Add tests for lower-case byte spelling based on observed native semantics, literal added `▁` and `<0x41>` tokens, NUL discrepancies and token-ID gaps. If the stated pipeline cannot be proven lossless for a case, keep that case blocked and report the boundary; do not weaken runtime equality.

Acceptance: `OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 uv run pytest -q tests/test_stance_tokenizer_adapters.py tests/test_structured_output.py`; `uv lock --check`; `git diff --check`; full thread-bounded pytest. Independent review must reproduce byte integrity and special masking before commit. Remote metadata-only vocabulary verification may follow separately; actual checkpoint/channel certification remains another gate.

## 4. Audit skeleton

Core claim: exact token bytes and declared control tokens can be supported without loosening primary decision validity. Necessary lines: narrow decoder shape, independent bytes/runtime equality, factory-bound provenance, validated special membership. Deferred details: native channel generation and resolution of actual checkpoint stop declarations; neither is implied by this slice.
