# LC0 validates a complete baseline once before localization

**Goal:** Load the immutable full-population baseline as a read-only parent for generated localization. Avoid reopening the writable store and rebuilding the 2012-key plan for each row. This slice is a parent consumer, not a localization experiment or an eligibility certificate.

## 1. Scope stays below experiment design

Create `llm_bias/core/stance_baseline_parent.py` and `tests/test_stance_baseline_parent.py`. Do not change baseline files, existing storage/adapter semantics, historical outputs, population pins, generation drivers or dependencies. Support the current complete single-shard layout only (`shard-0-of-1`); reject partial or multi-shard parents explicitly. No checkpoint loading, tokenizer decoding, GPU calls, donor selection, layer selection or research eligibility promotion.

Grounding: 【已驗證: llm_bias/core/stance_baseline_store.py:_parse,_generation】 strict canonical UTF-8 import helpers and lossless result import already exist. 【已驗證: llm_bias/core/stance_baseline_adapter.py:_validate_generation_result】 validates token hash, types, structural outcome/failure consistency. 【已驗證: llm_bias/core/stance_baseline_plan.py:build_baseline_plan】 validates the approved full input bundle and builds all2012 keys. 【已驗證: scripts/run_stance_baseline.py:build_identity,summary】 defines metadata binding hashes and the exact diagnostic summary. 【已驗證: llm_bias/core/inference/structured_output.py:validate_decision_payload】 parses the entire ordered decision object, without salvage.

## 2. The new consumer returns a snapshot, not authority over the model

**REQ-LC0-1 【新設計】** Public API:

```python
load_completed_baseline(directory: str | Path, *, inputs: BaselineInputs) -> CompletedBaseline
```

`CompletedBaseline` exposes `plan: ExperimentPlan`, `rows: tuple[ExecutionRow, ...]`, `parent_sha256: str`, `generation_for(key: RowKey) -> StructuredGenerationResult`, and defensive JSON properties `metadata`, `summary`, `file_sha256`. Store generation exports internally as immutable canonical bytes and import anew on access. Unknown keys reject. No writable methods/context manager. Public construction, if possible, is explicitly trusted and does not attest successful loader use. The loader returns a fully materialized snapshot; subsequent changes to source files cannot change the returned object. No residual/tensor fields.

**REQ-LC0-2 【新設計】** Validate a nonsymlink root with exactly `shard-0-of-1.execution_metadata.json`, `shard-0-of-1.summary.json`, `shard-0-of-1`. The shard has exactly `registration.json`, `store.lock`, `records`. The lock must be an existing regular nonsymlink file. Acquire a read-only shared nonblocking flock while collecting the snapshot; an active writable store must reject immediately. Check lock inode identity after acquisition. Never create or alter the lock or any file. Files and directory leaves must be regular/nonsymlink as appropriate; use no-follow descriptor reads to avoid path replacement between validation and read. Reject unexpected files, staging leftovers, missing layout, unsupported shard counts, invalid UTF-8, duplicate keys, nonfinite values and noncanonical JSON. Release descriptors/lock on success or any failure. Missing summary is not complete.

**REQ-LC0-3 【新設計】** Import `registration.plan` through `ExperimentPlan.from_dict`; require exact registration fields/schema_version1/index0/count1 and pinned input manifest. Rebuild the approved complete baseline once and compare canonical plan bytes. Do not call `baseline_execution_row` or rebuild the plan per record. Expected filenames are `sha256_json(key.to_dict()) + '.json'`; actual filenames must be exactly the complete2012-key set. Each envelope has the exact BS1 six fields and genuine integer version/index/count. Bind key, plan hash, condition/trial/ticker and issuer to the approved plan/population; reject extras/duplicates/missing rows.

**REQ-LC0-4 【新設計】** Each generation is imported with `_generation` and `_validate_generation_result`. Reconstruct its `GenerationOutcome` using the verified member issuer and require exact stored row equality. Reparse `json_payload` with `validate_decision_payload` (use empty payload if decode_error is non-null); require all three diagnostic flags to match that parse. Success must match parsed primary decision/reason and have no parse failure; failed generation must retain null primary decision/reason. Payload failure names invalid_json/invalid_schema/invalid_reason must match the parser; priority execution failures exception/timeout/no_legal_token/truncated/unsupported_channel/unsupported_tokenizer must not be replaced by the parser's secondary failure. Do not require all rows to succeed: complete failed rows remain executed.

**REQ-LC0-5 【新設計】** Metadata exact outer fields `identity`, `bindings`, `inputs_manifest_sha256`; identity equals the imported plan. Bindings exact fields `protocol`, `template`, `generation_policy`, `model`, `code`, `backend`. Recompute the six corresponding binding hashes. Recompute schema hash from `DECISION_SCHEMA` and key order and body-template hash from `DECISION_TEMPLATE`, `_ENTITY_TEMPLATE`, `DECISION_INSTRUCTION`; compare the latter with `bindings.template.body_template_sha256` (not with the wrapper-inclusive PlanIdentity template hash). Input hashes are already checked by full-plan construction. Require baseline operator/parent `not_applicable`. Protocol must explicitly identify diagnostic_full_baseline_v1, all2012 planned rows/503 members, approved role/evidence hashes, all_approved_pairs_once, and false research/efficacy/protocol-freeze claims; do not promote gates. Policy is the exact five-field `StructuredGenerationPolicy` record; validate genuine types, finite positive timeout and supported channel route. Each result's provenance must match schema hash, generation-policy hash, full generation policy and HF controls. Tokenizer/head/grammar identity fields and stop token IDs, when used by generation, must be consistent across rows; genuine IDs must lie in the declared head range. These checks certify consistency of recorded claims, not live checkpoint contents or authenticity of prompt generation. Do not compare historical source hashes to future working-tree changes; that is separate provenance auditing.

**REQ-LC0-6 【新設計】** Recompute the entire exact runner summary from imported rows/generations: assigned/executed/planned2012, missing0, complete_shard/global true, index0/count1, plan hash, class/failure/finish counts and all original named gates false. Strict boolean/type/canonical comparison, not Python bool==int equivalence. Reject summary differences or research_eligible/steering_flips_claimed true. Do not alter the parent summary.

**REQ-LC0-7 【新設計】** Hash every consumed data file except `store.lock`, keyed by root-relative POSIX path. Define `parent_sha256 = sha256_json({'kind': 'completed_baseline_parent_v1', 'files': file_sha256})`; exclude absolute path and mutable lock metadata, include registration/metadata/summary/all records. This is the snapshot's content identity, not approval from a mutable audit report. Same bytes at another path must have identical parent hash; changed reason/IDs with updated row/hash/summary changes the parent identity. All exported mappings are defensive copies.

## 3. Slice LC0 is one independently testable commit

Consumes verified B0/B1/BS1/B2 APIs and strict parser. Produces the new read-only parent API and tests only. Synthetic fixture topology: use the actual pinned full input pack (like `tests/test_stance_baseline_adapter.py:bundle`) with all2012 synthetic record exports and metadata bindings constructed consistently with schema/template/policy. Use direct temporary canonical fixtures, not2012 calls through the writable store. Do not add a public smaller-cohort override. A fake generation is permitted; label fixture provenance unverified.

Red: demonstrate absent consumer, corrupt registration/record/token hash/issuer/payload/metadata/provenance/summary, partial keys, policy bool/NaN, symlinks/staging/active writer, defensive-copy and file-identity failures. Green: implement one full-plan reconstruction plus linear per-record checks; instrument reconstruction call count so per-row rebuilding fails. Cover plain and Harmony full-text preservation, successful buy/sell, all nine priority failure causes with parser-consistent flags, missing/no extra keys, source snapshot immutability, copied directory same hash, failed load cleanup and real cooperating-process flock rejection. Reuse existing small fake-generation test helpers only when their flags/payload/provenance conform to this stricter consumer.

Acceptance commands:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 uv run pytest -q tests/test_stance_baseline_parent.py tests/test_stance_baseline_inputs.py tests/test_stance_baseline_plan.py tests/test_stance_baseline_adapter.py tests/test_stance_baseline_store.py
uv lock --check
git diff --check
```

Main and independent review must also load the actual retrieved GLM parent read-only, verify2012 rows, parent hash stability and unchanged hashes of the original directory. The actual GLM parent exercises plain-channel success only; all nine failure cases and Harmony preservation require synthetic fixtures. The consumer must finish without the previous per-row full-plan rebuild cost; record wall time rather than promising an unmeasured threshold. Preflight verified the naive linear real-parent scan with one plan reconstruction; timings are observations, not a protocol gate. Then full fake-model regression runs through a tracked background command. Commit boundary: LC0 accepted; subsequent pair/alignment/execution/runner slices have their own contracts and cannot be assumed implemented.

## 4. Argument skeleton

The engineering decision is to validate one immutable full parent snapshot before generating localization plans. Completeness/record integrity, read-only lifecycle and content identity are necessary; donor policy and scientific selection remain outside LC0. This separates expensive historical-parent validation from per-intervention execution without weakening the full-population requirement.
