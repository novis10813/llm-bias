# Structured-output decoding implementation spec

Goal: a new local HF greedy-generation path must apply a grammar while decoding, keep both decisions reachable, and produce strict completion/failure diagnostics. This slice does not certify all four real checkpoints. Preserve historical generation/parser behavior.

## Grounded interfaces and boundary

Verified `llm_bias/core/inference/generation.py:GenerationConfig` holds generation controls; `generate_tokens` directly calls `model.hf_model.generate` and cannot currently take arbitrary HF processors. Implement a separate wrapper rather than changing historical defaults.
Verified `llm_bias/core/inference/interventions.py:residual_interventions` remains active around model HF generation; processors act after forward hooks. Actual real-model compatibility still requires GPU evidence.
Candidate dependency: PyPI provides xgrammar 0.2.8 CPython3.13 Linux wheels. Pin exactly using `uv add 'xgrammar==0.2.8'`; confirm release API from installed source, do not rely on unversioned documentation. Docs: https://xgrammar.mlc.ai/docs/latest/start/quick_start.html and https://xgrammar.mlc.ai/docs/latest/api/python/grammar_compiler.html.

Non-goals: no fixed-prefix scoring, forced enum, regex/complete-object salvage, automatic channel stripping, static approximation to neuron edits, GPU run or new formal research protocol. GPT-OSS Harmony is explicitly unsupported in this initial plain-JSON capability unless separately validated in a later channel-aware slice. Do not infer that low reasoning disables analysis. No claim all models support plain content generation.

## Numbered requirements (new design)

REQ-S1: create `configs/concept-cone-steering/rebuild-v1/decision.schema.json` exactly object type, ordered properties decision enum [buy,sell], reason string minLength1, required [decision,reason], additionalProperties false. Load/validate schema once; reject any structurally different schema or enum omission. Schema bytes/hash are provenance, not the protocol freeze. `compile_decision_grammar(tokenizer, head_vocab_size, stop_token_ids)` constructs `TokenizerInfo.from_huggingface` and compiler with explicit ordered-key/strict semantics supported by pinned release. Head size is positive and covers tokenizer IDs; stop IDs unique integers inside head range. Fresh matcher/processor each generation; compiled grammar can be reused with bound tokenizer/schema/backend identity. No reuse of a mutable processor.

REQ-S2: apply grammar to a single batch-one greedy HF generate; explicit max_new_tokens>0, use_cache, stopping IDs, pad ID and monotonic timeout. Supply no sampling, beam search, answer prefill, arbitrary processor override, or margin. Add an independent no-legal-finite-token guard after grammar masking, raising a typed error rather than argmax of all -inf/NaN. Timeout yields a failure outcome; all hooks clean up on exceptions. Detect grammar closure with valid model stop tokens; record actual completion from complete strict JSON, not whether generate returned early. Token budget exhaustion is truncated if object is incomplete, but a complete valid object at exact budget is valid with finish_reason=`schema_complete` and failure_type=null. Record generated token sequence and token hash (permitted output tokens, not activation tensor), full decoded continuation without silent special-token deletion, separate JSON payload that removes only explicitly recognized terminal stop token(s) at the sequence end (never interior/channel markers), elapsed time, backend/schema/tokenizer/head/stop/cache/policy identity.

REQ-S3: `StructuredGenerationResult` stores generated text/IDs, decision (buy/sell/null), reason (str/null), decision_complete, schema_complete, reason_valid, finish_reason and failure_type. Strict parser uses duplicate-key rejection, exact field order, exactly two keys, legal enum and string reason; no fences, prefixes, trailing nonwhitespace or arbitrary channel words. Whitespace-only reason gives invalid_reason even when structurally complete. Partial output never supplies a primary decision/flip; `decision_complete` may be diagnostic only if established by grammar state, otherwise false. Enumerate finish/failure values consistently with docs/dev/stance_rebuild_p0_spec.md REQ-6. Never store logits/hidden states/KV/gradients. A recorded exception does not mark compatibility valid.

REQ-S4: `channel_policy` is explicit `plain_json` or `unsupported`; no defaulting from a model slug. `unsupported` fails before generate and returns unsupported_channel diagnostic. Frozen future model configs must separately prove template prefix already at response content and channel behavior. Initial wrapper cannot strip Harmony analysis/final or Gemma thought tokens. Special non-stop channel tokens in continuation cannot be silently removed; classify unsupported_channel. Do not mutate tokenizer/chat template or head vocabulary to make a mismatch pass.
