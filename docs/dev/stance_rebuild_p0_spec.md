**Goal:** implement the fixture-tested population, plan, prompt and generated-outcome contracts required before any TODO research run.
**Architecture:** new shared modules in `llm_bias/core/`; keep confirmation and other historical entrypoints unchanged. This spec covers the first independently verifiable milestone, not completion of localization/neuron/DIM/cone experiments.

## 2. Numbered requirements (all interfaces below are new designs)

**REQ-1 Population:** `PopulationMember(ticker: str, name: str, sector: str, issuer_id: str)`. `load_population(csv_path, issuer_by_ticker)` checks the exact CSV digest above before parsing, selects exactly 503 unique nonblank ticker/name/sector rows, and requires issuer mapping keys exactly equal membership with nonblank IDs. Preserve share classes and Unspecified. Return `PopulationSnapshot(members: tuple[PopulationMember, ...], source_sha256: str, membership_sha256: str)` sorted by ticker. Membership hash payload is the sorted list of member objects with ticker/name/sector/issuer_id fields; canonical JSON uses sorted keys, compact separators, UTF-8. Factor pure `validate_population_rows(rows)` with fixed expected_count=503 for independent synthetic coverage tests; it checks selection, fields/count/duplicates, without offering any alternative source digest or research loader option. `validate_members(members)` accepts tiny unit fixtures and checks nonempty unique nonblank members. Neither fixture validator is a research CLI.

**REQ-2 Roles:** `validate_roles(members, roles)` accepts exactly fit/validation/calibration/evaluation lists. Their disjoint union equals membership; every issuer is wholly in one role. `assign_roles(members, seed, issuer_counts)` shuffles sorted issuer IDs with `random.Random(seed)` and slices in fixed order (fit, validation, calibration, evaluation), using explicitly requested counts whose sum equals issuer count. Reject negative/noninteger counts, empty roles, unknown/duplicate tickers, missing issuer metadata and crossings. Return `RoleAssignments(roles: dict[str, list[str]], assignments: dict[str, str], ticker_counts: dict[str, int], issuer_counts: dict[str, int], assignment_hash: str)`; assignments maps ticker to role and roles maps role to sorted tickers. Hash payload is `{"roles": {role: sorted(tickers)}}`. `validate_roles` returns the same validated result. Only fit may provide operator-fitting inputs; selection consumes validation, dose calibration consumes calibration, final outcomes consume evaluation. `require_role(tickers, assignments, allowed_roles)` enforces membership and allowed roles, rejecting duplicates.

**REQ-3 Evidence:** an evidence item has string fields `item_id`, `text`, `polarity` (+/-), `source`, `source_sha256`, `content_sha256`, `review_id`, `strength` (a documented nonblank label), `numerical_review`, and `source_quality_review`. All strings are nonblank; both hashes are 64 lowercase hexadecimal characters. `content_sha256` is SHA-256 of exact UTF-8 text; `source_sha256` identifies reviewed source bytes and is supplied, not guessed. A pair has `ticker`, `trial_id`, `condition` (++,+-,-+,--), `evidence1`, `evidence2`. Validate exact coverage of every member × declared trial × four conditions, unique row keys, two nonblank independently identified slots, matching polarity, metadata completeness and recomputed content hash. Main evidence bytes/metadata must be shared across tickers. Explicit `order_contrasts` pairs require swapped identical item IDs and content, not merely opposite polarities. Do not silently convert old four-slot pools or infer financial truth. The schema and validation API must be documented in module dataclasses; source hash is provenance, not proof of quality.

**REQ-4 Generation prompt:** `DecisionPrompt` stores raw and rendered text, inference token IDs, four individually named spans (entity/evidence1/evidence2/instruction), per-span IDs/hash/role, prompt/template/schema hashes and wrapper policy. New renderer emits company ticker/name/sector, evidence slot 1, slot 2, then one fixed instruction requesting ordered decision/reason JSON with either buy or sell legal. Spans originate from known rendering offsets, not searching ambiguous evidence text. An optional system message must be explicitly provided and must not duplicate task instructions; chat kwargs and special-token policy enter provenance. Ensure rendered content contains the exact body once; reject rewritten/duplicated bodies. No score_ids, buy_id/sell_id, fixed answer prefix or margin. Evidence order contrasts change only slot order. Recompute span token IDs using the actual rendered inference input, including wrapper offsets. A tokenizer without reliable offsets is an explicit unsupported error, not a guessed mapping.

**REQ-5 Frozen execution:** `RowKey(stage: str, ticker: str, condition: str, trial_id: str, arm: str, dose: str)` uses nonblank strings and a canonical finite decimal string for dose (`0`, `0.5`, `-1`, without exponent notation or trailing zeros). `ExperimentPlan` freeze a nonempty, unique set of row keys before execution. Plan identity includes protocol/population/issuer/roles/evidence/schema/template/model/code/backend/generation-policy/operator/parent hashes (explicit `not_applicable` allowed only for operator/parent when baseline). Plan hash payload is `{"identity": identity, "keys": sorted_key_dicts}`. Conditions use literal `++`, `+-`, `-+`, `--`. `canonical_dose_str` normalizes finite str/int/float/Decimal via Decimal(str(value)) and rejects bool/NaN/infinity, exponent output, and negative zero. Deterministic sharding uses full SHA-256 integer of canonical key JSON modulo positive num_shards, never Python hash(); no ticker selection. `validate_rows` rejects duplicate/foreign rows. Missing rows yield progress; complete requires exact coverage. A completed generation failure is a row; an unexecuted row is absent. Resume requires exact identity hashes and planned keys. Merge rejects duplicate shards/overlapping row keys, incompatible identities and unexpected rows. Eligibility requires complete coverage and all declared gates passed; reject a claimed complete/eligible flag contradicting computed state.

**REQ-6 Outcomes:** a generation outcome stores ticker/issuer/condition/trial identity, `decision` (buy/sell/null), `decision_complete`, `schema_complete`, `reason_valid`, `finish_reason`, and `failure_type` (null or `truncated`, `timeout`, `exception`, `no_legal_token`, `invalid_json`, `invalid_schema`, `invalid_reason`, `unsupported_channel`). `finish_reason` is `eos`, `schema_complete`, `token_budget`, `timeout`, `exception`, `no_legal_token` or `unsupported`. A failure cannot also be primary-valid. A primary-valid outcome requires a complete schema, nonblank valid reason and legal complete decision. Rows contain generated text/token provenance optionally but require no scoring fields. Pure outcome validator rejects contradictory statuses. Existing complete-object/regex parsing is not primary schema completion.

**REQ-7 ITT:** metrics start from an explicit planned key list and paired baseline/intervention outcomes, not rows observed on either side. Reject missing/duplicate/extra keys for complete summaries. For each direction, denominator is all primary-valid baseline source-class planned units; invalid/truncated interventions count as not flipped, with denominator unchanged. No source class means rate null/NA. Report planned N, baseline buy/sell/unknown, directional denominator/flip/retention/off-target counts, completion/failure counts and observed flips/planned N. For each condition/direction, let d_k be the count of primary-valid source-class baseline trials for ticker k, and f_k the flipped count (invalid intervention counts zero). Ticker rate y_k=f_k/d_k exists only when d_k>0. Primary rate is the unweighted mean of eligible ticker rates, not ratio of sums. Report the secondary micro rate=sum(f_k)/sum(d_k), both denominators, and source-free ticker count. Bootstrap requires explicit seed, samples and confidence level from the future frozen protocol (no implicit research defaults). Resample all planned unique issuers with replacement, retaining every eligible ticker's y_k in each sampled occurrence; mean those ticker rates for each draw, track zero-eligible undefined draws, and percentile-quantile the finite draws. Paired method differences use the same sampled issuer occurrences. Trials remain within tickers and share classes remain within issuer clusters. Expose micro counts and planned ticker/issuer/trial N separately. No conditional two-valid denominator as primary. A progress-only helper may report coverage without efficacy or eligible result.

## 4. Acceptance and remaining research coverage

P0 milestone passes only when all four slices pass independent code/spec review and full tests. It does not authorize a GPU research run. Subsequent specs must cover constrained grammar/channel decoding; cache-aware hook/no-op gates; full-manifest baseline; all-layer generated localization; real neuron discovery; generated-label 1D DIM/addition/ablation; independent sequence-trained cone/ray acceptance; common controls/calibration; geometry/component-removal; blinded reasons/counterfactuals; robustness, immutable historical audit, result provenance and paper updates. Human annotation cannot be marked done without actual blind labels/agreement. Record missing/unsupported/untestable/negative separately.

Structural rationale: population/roles establish the units; evidence/rendering establish interventions' inputs; frozen execution establishes accounting; ITT establishes reported outcomes. Operator implementations depend on all four and cannot select on evaluation.
