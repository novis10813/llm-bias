# Four-arm no-op execution must retain real attempts and never invent a control

**Goal:** Integrate one prepared prompt with actual baseline, repeat, zero-addition and prompt self-replacement generation. Read-only preflight verified the execution interfaces and required an explicit result-construction consistency contract; this revision includes that amendment. It does not execute the full population, certify coverage or freeze checkpoint policy.

## 1. Accepted components supply the execution boundary

【已驗證: `llm_bias/core/inference/structured_output.py:generate_structured`】 A plain factory capability plus explicit policy drives one greedy HF generate call; caller/binding errors raise before execution, runtime failures return StructuredGenerationResult. `transforms=None` avoids double registration with external scoped contexts.

【已驗證: `llm_bias/core/inference/harmony_generation.py:generate_harmony_structured`】 A Harmony factory capability requires harmony_no_tools and the bound native prompt suffix. It returns the same result type with complete analysis/envelope/final output. Neither driver permits injected final headers or a separate source forward.

【已驗證: `llm_bias/core/inference/stance_transient_capture.py:capture_prompt_residual`】 TC1 captures the first full prompt at a registered site, ignores fresh replay after the original tracker exits, and releases its source on context exit. Failed first root forwards invalidate source. Later generation failure can leave a valid first source: source readiness and generation success are independent.

【已驗證: `llm_bias/core/stance_baseline_adapter.py:baseline_gate_input`】 B2 validates each result and copies complete IDs/text/status without reparsing. Existing `evaluate_noop_gate` compares four genuine inputs, returns false for invalid/mismatched output and exposes compact diagnostics. Existing replacement supports prompt_only only; this slice uses that same scope for zero and self.

## 2. One function executes one explicitly configured prompt

All interfaces below are 【新設計】. Create only `llm_bias/core/inference/stance_noop_execution.py` and `tests/test_stance_noop_execution.py`. No accepted-module edits, rendering, model loading, CLI, sharding/resume, manifest compiler, full-plan execution, real checkpoint/GPU run, raw source persistence or eligibility shortcuts.

`execute_prompt_noop(model, tokenizer, prompt_ids, capability, *, policy, layer, hook_site, zero_vector, prompt_positions=None, config_hash, verified_binding=None) -> PromptNoOpExecution` accepts an already prepared integer batch-one tensor. The future renderer consumer constructs it from DecisionPrompt.inference_token_ids without retokenizing a span. Do not infer its device or wrapper from a model slug.

**REQ-NO.1 — Validate configuration and route explicitly.** Require lowercase64hex config_hash; genuine integer in-range layer; supported pre/mid/post target; nonempty unique prompt positions in range (None=full prompt), preserving caller order. Require finite nonzero floating 1D zero_vector with positive width; snapshot it with detach().clone() once before calls, so caller mutation cannot alter subsequent controls. It is a direction, not a captured residual; never export its values here. Validate input tensor/dtype/head range, explicit policy, factory capability, tokenizer/model binding, and Harmony suffix through accepted helpers before any generation. Route plain capability only with plain_json, Harmony capability only with harmony_no_tools; unsupported policy is an invocation error, not an invented executed result. No arbitrary driver kwargs, sampling, header injection or generated-token substitution. Caller-supplied config_hash is labeled unverified configuration identity until a later manifest compiler binds it to actual operands; this function cannot certify that external hash claim.

**REQ-NO.2 — Capture and execute genuine arms in order.** Use a fresh GenerationPositionTracker per generate call. Enter baseline tracking before capture with separate ExitStacks so the original tracker closes before repeat/zero/self, while capture stays alive until self completes. Baseline runs under observational capture with no intervention transforms. Validate its returned result via baseline_gate_input immediately. If baseline.failure_type is not None, return a halted record containing only the real baseline result, regardless of holder.ready; record halt_reason=baseline_failed. Otherwise try holder.require_source(); if unavailable, return a halted record containing only baseline with halt_reason=source_unavailable. Do not fabricate a self result, execute a separate source/scoring forward, or promote output success to capture success. Examples: a custom generate bypassing root calls may produce valid output but no source; a failure after successful prefill may retain source but must still halt.

With successful baseline and available source, execute repeat with a fresh tracker and no perturbation, zero with another tracker plus scoped_residual_intervention(operation=addition,dose=0.0,vector=snapshot,scope=prompt_only), then self with a final tracker plus replacement(scope=prompt_only,dose=1,source=source,source_positions=captured positions,prompt_positions=captured positions). Same layer/site/selection, prompt IDs, capability, tokenizer and policy apply to all arms. Self has no vector. Full drivers remain active across the entire native Harmony analysis/final turn. Repeat or zero runtime failure does not skip the remaining executable controls: retain all genuine returned results and let the pure gate report false. Driver invocation errors and malformed returned results raise ValueError or the existing specific caller exception; do not absorb them into synthetic GenerationOutcome records.

**REQ-NO.3 — Return only executed results and compact state.** `PromptNoOpExecution` is frozen with slots and fields: baseline:StructuredGenerationResult, repeat:StructuredGenerationResult|None, zero:StructuredGenerationResult|None, self_replacement:StructuredGenerationResult|None, gate:NoOpGateResult|None, halt_reason:str|None. Legal halted reason strings are baseline_failed/source_unavailable, with all later arms and gate None. A completed invocation has all four real results, gate, and halt_reason=None even if gate.passed=False. A gate failure is not an execution halt. `completed` is a read-only derived property (all four results and gate present with no halt reason); `passed` is false if halted, otherwise gate.passed. Do not provide research_eligible or an as_gate_dict convenience that silently converts an unexecuted control into a complete certificate. Expose zero_diagnostics/self_diagnostics as defensive scalar dictionaries or None backed by private canonical JSON bytes, following accepted PerturbationDiagnostics.to_dict shapes. Halted records have neither diagnostic set. No source tensor, vector, tracker, masks, KV cache or hook handle escapes in the result. Preserve each driver's failure/finish and complete IDs/text unchanged. No persistence API in this slice. Construction validates each present generation result through baseline_gate_input without coercion or reparsing. Legal cross-field states are exactly: baseline_failed requires a non-null baseline failure and all later results/gate/diagnostics absent; source_unavailable requires a successful baseline and all later results/gate/diagnostics absent; completed requires a successful baseline, all three later results, gate, both diagnostic sets and halt_reason=None. Later results may contain genuine execution failures. Recompute evaluate_noop_gate from the four validated results using the supplied gate.config_hash and compare its complete compact export to the supplied gate; reject unrelated or contradictory gates rather than repairing them. Both private diagnostic byte records must parse as strict duplicate-free/nonfinite-free canonical JSON objects with the exact accepted PerturbationDiagnostics scalar fields, matching genuine nonnegative layer and supported hook_site across both records, scope=prompt_only, operation=addition for zero and replacement for self, finite numeric values and genuine nonnegative integer counts; their getters return fresh dictionaries. These checks establish structural consistency, not proof of execution for arbitrary caller-constructed synthetic objects.

**REQ-NO.4 — Cleanup cannot depend on generation success.** Nested contexts remove their own hooks and clear active positions after normal/halted/exception exit, while preserving unrelated hooks. Capture lifetime drops its source reference; the executor must also delete/drop its own source reference before returning or propagating errors. No lasting tensor-valued model attributes. No garbage-collection timing or empty_cache calls as substitutes for reference cleanup. This component trusts the caller's unperturbed baseline environment: arbitrary unrelated external intervention hooks cannot be proven absent here.

## 3. NO1 has a real root-forward CPU fixture

Tests must use actual installed xgrammar/native tokenizers and real torch root/module hooks, never monkeypatch four canned results as the only verification. Existing `tests/test_structured_output.py:FakeGenerate` calls a block directly and bypasses root hooks; it cannot establish this integration. Build a tiny nn.Module root with two hookable blocks/post_attention_layernorm; its generate loop invokes `self(...)` through Module.__call__ at every autoregressive step, respecting accepted logits processors/stopping criteria. First call has the full prompt; subsequent cached calls have validated explicit/legacy positions, or no-cache full prefix recomputation. Seed greedy target tokens deterministically; no checkpoint.

Verify all sites, ordered subset [2,0], both cache modes and actual plain/Harmony drivers: exact complete-output equality across four arms, zero/self changed_token_count=0 and nonzero selected_token_opportunities, correct analysis/header retention, exactly four HF generate calls, zero-vector identity versus rejected all-zero/NaN/wrong dimension inputs. Wrong dimension must not produce a passing control; if baseline width is only known at capture, reject before starting repeat/zero/self rather than rely on a swallowed zero hook error. Tests distinguish baseline runtime failure, source-unavailable valid output from root-bypassing fake, and repeat/zero/self runtime failures: count actual calls and None controls, preserve exact failure strings and false gates. Inject hooks/registration failures and driver-caught tracking errors; assert no owned hooks survive, unrelated hooks remain, no raw-source result fields, and source access is released. Malformed caller inputs or structurally malformed/inconsistent typed results raise; structurally valid synthetic values cannot be authenticated as executed from type alone. Test malformed nested results, contradictory halt reasons, partial-arm records, absent completed diagnostics, unrelated but individually valid gates, malformed/noncanonical diagnostic bytes and mutation of exported dictionaries.
