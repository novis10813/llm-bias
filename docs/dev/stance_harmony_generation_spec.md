# Native Harmony boundaries must govern final JSON decoding

**Goal:** Generate an assistant turn in one greedy HF call, retaining model-generated analysis and headers, and activate the canonical decision grammar only inside the native final message. Do not inject an answer or final header. Engineering acceptance does not certify a checkpoint or authorize research runs.

## 1. Evidence separates historical behavior from new capability

Verified existing APIs in `core/inference/structured_output.py`: factory-owned `CompiledDecisionGrammar`, `compile_decision_grammar(tokenizer,head_vocab_size,stop_token_ids)`, `_check_capability`, `_bind_model`, `_hf_controls`, `FiniteLegalTokenGuard`, `validate_decision_payload`, and `StructuredGenerationResult`. Current `generate_structured` admits only plain_json/unsupported and applies its matcher from continuation step0. T1 adapter changes are separate and must be independently accepted before C2 integration.

Read-only historical audit found complete continuation IDs only in GPT-OSS `confirmation-v1-20260925-full-01/alpha0/result.json`, SHA-256 `0e6d4e5fab58fac1fecf05906c6b1d5ff6e0bfb688ca09225c52d599a28e1f03`. Its935 baseline rows contain native analysis then final headers. Other arms' realized_token_ids are answer-pair readout IDs, not whole outputs. This does not prove rebuild-v1 compatibility or all steered transitions. The audit refuted a guaranteed192-token completion at reasoning_effort=low. No enforced analysis cap or forced transition is introduced here.

Official Harmony format distinguishes message end from assistant-turn return: https://github.com/openai/harmony/blob/main/docs/format.md . Model-specific IDs and literal spellings require verified tokenizer bindings; no slug inference. The report's statement calling token200002 message-end is a label error: it denotes the assistant return in the inspected checkpoint, not internal message-end200007. Its sample FSM and suggested120-token forced analysis transition are not adopted.

Non-goals: tools/recipients/commentary, multimodal output, generic channel framework, arbitrary runtime tokenization of header words, posthoc regex/subsequence salvage, channel deletion, stop-binding relaxation, logit synthesis, EOS injection, model loading/GPU, protocol/model-config freeze. Preserve legacy generation and historical artifacts.

## 2. Numbered requirements define a narrow no-tool protocol

**REQ-C1 — Explicit immutable token contract (new design).** New `HarmonyTokenContract` frozen/slotted record fields: `prompt_suffix_ids`, `initial_analysis_header_ids`, `initial_final_header_ids`, `message_end_id`, `assistant_restart_ids`, `final_stop_id`, `forbidden_control_ids`. All sequences become immutable tuples of genuine nonbool nonnegative ints; reject strings/bytes/mappings, empty required sequences, duplicates where they make branch matching ambiguous, or inconsistent header shapes. Both headers have length>=3 (channel marker, at least one ordinary channel-name ID, message marker); restart has length>=2 (start marker and at least one ordinary role ID). Header alternatives may share prefixes but neither may equal/be a prefix of the other. Repeated ordinary word IDs within a header are permitted when the two complete sequences remain unambiguous; forbidden_control_ids must be unique and disjoint from every admitted sequence ID. prompt_suffix_ids must equal assistant_restart_ids for this deliberately narrow open-assistant prompt contract. Initial headers end in the same message-marker token and begin in the same channel-marker token. `assistant_restart_ids` excludes message_end and represents message start+assistant-role literal; it is followed by either initial header after an analysis ends. Message-end, final-stop, channel-marker, message-marker and restart-start are distinct; forbidden controls cannot overlap admitted controls. Ordinary role/channel names can be multiple IDs, pinned explicitly rather than assumed single tokens. No hardcoded experimental checkpoint IDs in reusable logic.

Proposed inspected GPT example: suffix(200006,173781), analysis header(200005,35644,200008), final header(200005,17196,200008), message_end200007, restart(200006,173781), final_stop200002, forbidden includes tool-call200012/schema-control200003/context-end199999. These are illustrative metadata, not default parameters or automatic verification.

**REQ-C2 — Pure incremental state machine (new design).** Create `HarmonyBoundaryTracker(contract, *, special_token_ids)` with an immutable validated tuple of genuine nonbool nonnegative special IDs (reject duplicates and require all contract control IDs included), and `observe(token_ids)` accepting the entire continuation prefix, validating all tokens and requiring prior observed prefix unchanged. Re-observing the same prefix is idempotent. Consume newly appended IDs one at a time with their actual absolute continuation indices, including a whole returned sequence in one call. Public defensive state: phase (`header`, `analysis`, `restart`, `final`, `terminated`), final_content_start:int|None, final_content_end:int|None, and analysis_segments:tuple[tuple[start,end],...]. Segment ends exclude message-end; final end excludes final-stop. analysis_segments contains only completed segments; an open analysis segment at budget exhaustion is not silently closed. Add read-only observed_token_ids:tuple[int,...], contract, special_token_ids and is_terminated:bool property. Public state properties cannot be reassigned. Store output IDs only, never hidden arrays. A local `UnsupportedHarmonyChannel(ValueError)` distinguishes protocol violations.

Initial header uses a prefix trie for analysis or direct-final. After a completed analysis header, all ordinary body tokens remain body regardless of words such as final or JSON text; only the exact declared message-end moves to restart. Restart must be the exact pinned assistant_restart_ids and a new analysis/final header. Phase remains restart during both the restart sequence and its following header trie; header denotes only the initial continuation header. Support zero-length and repeated analysis segments. Only one final body is allowed. Entering final sets the offset immediately after its header's final ID. Final-stop closes final and sets end; further IDs are rejected (no unexplained stop suffix). Premature final-stop, tool controls, unknown special controls and malformed header transitions fail. No final content is inferred from string searches.

`allowed_next_ids() -> tuple[int,...]|None` has no parameters because specials are already immutably bound; C2 separately checks full head range. This deliberate simplification supersedes the preflight's suggested optional head/special overrides. Return sorted unique alternatives. In header/restart this API reports the next legal ID but does not itself mask or synthesize tokens. header/restart returns exact possible next header IDs; analysis returns None to mean ordinary vocabulary plus message-end (caller constructs a safe mask using declared specials); final returns None because the JSON processor owns legality; terminated returns emptytuple. Unknown specials are rejected on observation. Bind `special_token_ids` immutably at tracker construction. Header word IDs must not be specials. On final-body observation allow ordinary IDs plus the declared final-stop, rejecting unknown specials; C2 separately validates ordinary IDs with the JSON matcher and excludes tokenizer mismatches. C1 consumes no tokenizer/HF/xgrammar imports and cannot validate JSON content; C2 owns grammar completion and stop legality.

**REQ-C3 — Factory binding before any model forward (new design).** Exact new capability name is `CompiledHarmonyDecisionGrammar`, frozen and eq=False, with fields `json_capability:CompiledDecisionGrammar`, `contract:HarmonyTokenContract`, `contract_sha256:str`. `contract_sha256` is sha256_json(asdict(contract)); accepted numeric IDs must first pass actual tokenizer/head bounds before hashing, including huge Python ints. Use a local WeakKeyDictionary factory registry and validate exact nested capability identity/metadata plus the existing JSON capability registry on every processor/generation creation. Never reconstruct from exported metadata. `new_processor(*,prompt_length:int,deadline:float|None)` returns a fresh `HarmonyDecisionProcessor`. The compiler and generator are exported by harmony_generation.py; current plain APIs retain signatures.

 C2 new `compile_harmony_decision_grammar(tokenizer,head_vocab_size,contract)` returns a process-local factory-owned capability containing the accepted JSON capability compiled with ONLY contract.final_stop_id, immutable contract and verified special vocabulary identity. Validate every contract ID against vocabulary/head range; control IDs must be declared specials and header words ordinary. Verify decoded literal suffix/headers/control spellings without runtime re-tokenization: `'<|start|>assistant'`, `'<|channel|>analysis<|message|>'`, `'<|channel|>final<|message|>'`, message-end `'<|end|>'`, final-stop `'<|return|>'`, restart `'<|start|>assistant'`. Reject mismatched spellings, prefix ambiguity or forged/replaced capability. Runtime prompt must end exactly in bound prompt_suffix_ids and tokenizer identity match. Existing model binding must agree with final-stop; don't treat internal message-end as EOS. A restricted subset of declared stops is allowed only by the existing binding rules, never overridden by caller attestation.

**REQ-C4 — One processor preserves native logits (new design).** `HarmonyDecisionProcessor` subclasses HF LogitsProcessor with `observe(input_ids:torch.Tensor)`, `check_timeout()`, `__call__(input_ids,scores)` and read-only boundary tracker access. `generated_token_ids` retains the complete observed prefix for diagnostics even when a newly observed token violates the protocol; the boundary tracker retains only the accepted prefix as C1 specifies. Prompt_length is positive genuineint; deadline is None or finite real nonbool, checked cooperatively with time.monotonic. Observation validates batch1 integer input IDs, unchanged already-observed continuation, all newly observed IDs in head range and any known blocked byte-mismatch/padded IDs before accepting the protocol. Header role IDs and admitted control IDs must have safe exact bytes. The plain capability's blocked special IDs must not be unmasked wholesale: only verified header control IDs/message-end are admitted in their exact phases, while mismatched/gap/padded IDs remain blocked everywhere. Processor returned prefix observations are idempotent. When processing a whole returned sequence, inspect pre-token phase, then advance boundary and matcher in the appropriate order; an early return token must fail rather than mark success.

 New Harmony processor shares the tracker and a fresh JSON matcher. During header/restart mask to admitted prefix-trie continuations while preserving original logits. During analysis permit ordinary IDs and message-end, block other special/padded/mismatched/forbidden IDs; do not cap analysis or force message-end. During final apply the accepted schema bitmask, blocking special IDs except the bound final-stop when the matcher is complete. Never write an allowed logit to0 or any synthetic value; a sole permitted ID with NaN/inf/-inf cannot be made legal. Independent FiniteLegalTokenGuard remains after masking. Feed only final-body tokens to matcher, and allow final-stop only after complete grammar. Any fake generate that bypasses masking is still validated on returned-sequence observation. Match offsets correctly for batched multi-ID observation; no analysis/header tokens reach matcher.

**REQ-C5 — Single HF call and exact diagnostic boundaries (new design).** Input errors (wrong policy, forged capability, mismatched tokenizer/head/stops/prompt suffix/shape/dtype) raise before forward; exceptions during actual execution become diagnostic failure results. Missing model declarations require the existing VerifiedModelBinding, which cannot override contradictions. Result decode mismatch retains the existing unsupported_tokenizer/unsupported diagnostic rather than coercing into another failure type; the later versioned execution adapter must account for it explicitly. No new failure types are introduced in C2.

 `generate_harmony_structured(model,tokenizer,prompt_ids,capability,*,policy,verified_binding=None)` accepts explicit `StructuredGenerationPolicy` with channel_policy='harmony_no_tools' (C2 adds only this policy literal, with plain generate explicitly rejecting it). Neutralize HF defaults using existing controls, no sampling/beams/prefill/forced tokens. Use one generate call and a paired observing stopping criterion, not caller-appended headers or multiple generation passes. Interventions are installed externally with tracker/scoped contexts and are active across the whole turn; this wrapper adds no separate transform API. HF calls may observe outputs at multiple points; repeated prefixes are harmless. Validate prefix/dtype/head/budget/early termination as in accepted plain path. Root failure/no-legal/timeout classification survives secondary decode errors.

Return existing `StructuredGenerationResult`: full generated_text and complete output IDs/hash preserve analysis and every header; json_payload is a decode of the exact final span, not regex-salvaged. No final boundary => emptypayload. Decode whole turn and final bytes with strict backend-byte/HF equality. Primary values exist only for a strictly valid final schema and no earlier failure. At exact total budget, a complete valid final JSON may finish schema_complete without return; incomplete header/analysis/final yields truncated/token_budget and decision/reasonNone. Before-budget unexplained incomplete return is exception. Unsupported protocol yields unsupported_channel/unsupported. Provenance binds contract, channel-policy hash, final offsets, analysis segment offsets and token counts; no extra copy of analysis text or raw arrays beyond already permitted generated output. Output offsets are derived, never used to retroactively repair malformed channels. An exact-budget valid final object does not need a return token; with budget remaining, use the matcher to admit terminal return without synthesizing its logit and let normal HF EOS handling stop. If a fake generation returns a complete schema without EOS before budget, retain the accepted plain path's schema_complete handling; an incomplete early return remains exception. One supplied policy.max_new_tokens budgets the entire output including analysis/headers/return, not an extra allowance per phase.

Exact channel provenance fields (in addition to the existing plain identity/backend/binding/policy/controls fields): channel_contract (all7 asdict fields with JSON-list IDs), channel_contract_sha256, channel_policy_sha256 (sha256_json({'policy':'harmony_no_tools','contract_sha256':contract_sha256})), final_content_start, final_content_end (ints/null), analysis_segments (list of [start,end] pairs), generated_token_count:int, final_token_count:int. On exact-budget completion without return, final_content_end remains null as the tracker specifies and final span runs to len(tokens). Bind identity/provenance before execution; create a new immutable canonical bytes result after adding derived offsets. No mutable external mapping is shared with the result. Whole-turn UTF-8 validation must include every header/control token; only final span is passed to strict decision validation. On root failure with a partial final payload, diagnostic parser flags may be retained, but primary decision/reason always clear.

## 4. Audit skeleton

Core claim: a verified native channel boundary, rather than posthoc parsing, determines where the canonical decision grammar applies. Necessary support: immutable explicit header binding, incremental channel state, strict final schema with preserved logits, and complete output diagnostics. Historical baseline transitions motivate the design but do not supply new experiment eligibility. Budgets and actual checkpoint capability remain full-plan execution gates.
