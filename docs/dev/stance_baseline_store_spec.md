# Baseline resume must preserve immutable full generation records

**Goal:** Add a plan-bound shard store of write-once baseline records. Initial read-only preflight required explicit initialization/lock/poisoning/import amendments. This revision includes them plus clarified post-link crash/late initialization-fsync semantics; final read-only preflight passed. Use one atomically published file per executed row instead of a torn-tail-prone append journal. No model runner, control-attempt store, gate certification or final shard publisher belongs to this slice.

## 1. Existing contracts separate execution coverage from generated output

【已驗證: `llm_bias/core/experiment_contract.py`】 `ExperimentPlan.keys_for_shard(index,count)` determines ownership. `ExecutionRow` stores compact status only; a failed outcome remains executed. `validate_resume` requires identical canonical plans. `ExecutionShard` needs explicit boolean gates and full merge needs every registered index, including empty shards. A store must not infer true gates from completed or empty coverage.

【已驗證: `llm_bias/core/stance_baseline_adapter.py:baseline_execution_row`】 The adapter rebinds the full approved input/plan before validating a generated result and deriving its compact row. `StructuredGenerationResult.to_dict()` preserves complete IDs/text/payload/reason/timing/provenance with no private bytes; it has no strict importer.

【已驗證: `llm_bias/core/artifact_paths.py`】 Canonical JSON uses sorted compact UTF8 without NaN. Existing atomic writers fsync a temporary file and replace a destination, so they do not guarantee no overwrite or directory fsync. This slice needs a local write-once publisher; do not alter accepted writers.

## 2. BS1 stores baseline rows only

All interfaces below are 【新設計】. Create only `llm_bias/core/stance_baseline_store.py` and `tests/test_stance_baseline_store.py`. No modifications to accepted contracts, input packs or historical outputs. No tensor/source/cache persistence, automatic recovery, generic artifact framework, model execution, CLI, control/gate files or `research_eligible` claims.

`open_baseline_store(directory, *, inputs: BaselineInputs, plan: ExperimentPlan, shard_index: int, num_shards: int) -> BaselineShardStore` revalidates the entire inputs and plan through B1 and rejects malformed/non-int indices or counts via `plan.keys_for_shard`. Directory is caller-selected within a later new run; enforce nonsymlink directory and regular nonsymlink artifacts, but do not invent run IDs/model slugs. Only create its final directory when its parent exists. The store is a context manager holding a Linux `fcntl.flock` exclusive nonblocking lock on `store.lock` for its complete lifetime. Concurrent open raises a specific RuntimeError; do not wait indefinitely. Acquire lock before reading or initializing registration; release on any failure and context exit. The factory immediately validates and acquires/initializes before returning; __enter__ returns that same open store without reacquisition. Provide idempotent close(); __exit__ closes and returns False. A closed store cannot be re-entered. All access/mutation methods reject a closed store. This is one shard per directory, not a shared global journal.

**REQ-BS.1 — Bind immutable registration.** Exact directory layout: `store.lock`, `registration.json`, `records/`. Only internal staging files named `.pending-<random>.tmp` may temporarily coexist in the directory being published to; such leftovers cause an explicit incomplete-store ValueError on reopen and are not removed automatically. Reject symlinks, unexpected files/directories, corrupt registration or records before exposing recorded coverage. For a fresh store, create a nonsymlink empty records directory and publish registration as canonical JSON plus terminal newline. Registration exact fields are schema_version=1, plan=plan.to_dict(), inputs_manifest_sha256=inputs.manifest_sha256, shard_index and num_shards. Existing registration must compare byte-identically with expected registration; changed plan/count/index cannot resume. Registration must exist before a record can publish. An interrupted initialization with missing registration or incomplete layout is an error, not fresh work to overwrite. The lock file contains no research data; its persistent inode is not an immutable research record. Never unlink, replace or truncate it, including failed opens and context exit. Use a nonsymlink opened directory descriptor and directory-relative operations. Open the lock with O_NOFOLLOW, no O_TRUNC, and verify fstat is regular; existing stores require an existing lock file. After nonblocking acquisition, require device/inode agreement with a nonsymlink directory-entry stat, otherwise release and raise. Continuous malicious replacement is outside cooperating-worker guarantees.

Only an invocation that exclusively mkdir-created the previously absent final directory may initialize it. Existing empty or lock-only directories are incomplete and rejected; do not infer freshness from absent registration or recreate missing pieces. Sequence after input/plan/index validation: exclusively mkdir final directory, open/acquire persistent lock, verify only that lock exists, create and fsync empty records directory, publish registration via root-local exclusive staging/file-fsync/no-overwrite-link/unlink, then fsync store directory and its parent before acknowledging successful initialization. A failed initializer never retries or treats the directory as fresh. Depending on failure stage, it may leave an incomplete layout or a complete observable registration. Reopen rejects incomplete layouts; a complete layout may reopen only through normal existing-store validation, which does not certify durability of the failed initialization attempt.

**REQ-BS.2 — Publish real baseline results once.** `store.record(key: RowKey, result: StructuredGenerationResult) -> ExecutionRow` checks ownership and calls baseline_execution_row. Serialize exact fields `schema_version:1`, `plan_hash`, `shard_index`, `num_shards`, `row:row.to_dict()`, `generation:result.to_dict()`. Filename is `sha256_json(key.to_dict()) + ".json"` in records. No sequential counter or truncated digest. Commit canonical UTF8 plus newline using a same-directory exclusive temporary file, file fsync, atomic no-overwrite publication (e.g. hard-link temporary inode to destination), remove temporary name, then fsync the records directory. Never replace an existing record, including a failed generation or byte-identical duplicate. Duplicate record raises ValueError without changing historical bytes. Clean up only the current invocation's own staging file on ordinary failure; abrupt-process staging leftovers remain observable on reopen. After successful publication, update in-memory recorded state; failures after publication raise and require reopen, never retry that key blindly. Once the destination link succeeds, any subsequent staging-unlink/directory-fsync/in-memory-update failure poisons the open store: coverage/read/write methods raise RuntimeError until close; only close/context exit remains allowed. Never delete the published destination or retry internally. Prepublication cleanup failure also poisons the store because its staging leftover violates layout. Cleanup may remove only its own staging name, even if already linked; preserve the original error if cleanup also fails. A failed directory fsync is not a durability-success acknowledgement; reopen validates observable state without retroactively certifying the failed fsync. Store-owned records are immutable; same-shard concurrency is excluded by the lock. No raw prompt/residual/logit fields.

**REQ-BS.3 — Validate full records on reopen.** Parse strict UTF8 JSON with duplicate-key rejection, nonfinite/overflow rejection and canonical whole-file bytes plus newline. Require exact top-level registration/entry fields and exact generation field set matching existing to_dict export (including error_message/decode_error). Reconstruct StructuredGenerationResult with generated_token_ids converted only from a JSON array to its declared tuple and `_provenance_bytes=canonical_json_bytes(generation["provenance"])`; do not repair any values or reparse payload text. Validate via the B2 adapter and require the derived ExecutionRow export to equal the stored row exactly. Compare canonical_json_bytes(reconstructed.to_dict()) with canonical_json_bytes(saved_generation), and likewise the derived/stored row exports; raw dictionary equality is incorrect because generation token tuples become JSON lists. Entry schema_version/shard_index/num_shards must be genuine Python integers (never bool/float), with exact expected values; also validate plan_hash, filename full-key digest, ownership and uniqueness. Importer requires the exact15 exported generation fields and a JSON list for generated_token_ids; remove provenance from constructor kwargs and provide _provenance_bytes=canonical_json_bytes(provenance), preserving other fields without coercion. Normalize malformed reconstruction/serialization errors to ValueError. Validate strict UTF8 strings and object keys at every depth, including escaped lone-surrogate rejection; strictness applies to outer records/structured provenance, not reparsing generated_text/json_payload strings. Genuine failed malformed payload text is preserved. Typed invalid generator states raise ValueError; no failed record gets dropped or retried. Consistent stored row identity proves key/outcome/issuer/ownership agreement, not that an otherwise valid generation originated from that prompt; provenance authentication is outside BS1. Counts or passed parse flags alone cannot authorize foreign records.

**REQ-BS.4 — Expose coverage without gate claims.** `recorded_keys -> tuple[RowKey,...]` and `rows -> tuple[ExecutionRow,...]` are sorted readonly properties; `pending_keys -> tuple[RowKey,...]` is assigned keys minus recorded keys. `generation_for(key) -> StructuredGenerationResult` returns a fresh reconstructed validated result from private canonical record bytes, raises KeyError when absent, and preserves full output (including Harmony envelopes). External mutation of returned dictionaries cannot change future reads. Store retains no generated tensor, live model or activation source. An assigned empty shard has empty recorded/pending tuples and registration, not fabricated true gates. No finalize/as_gate_dict/eligibility convenience in this slice. A later runner separately stores actual NO1 control attempts, coverage evidence and explicitly constructs registered final shards.

## 3. The crash policy is strict and observable

Write-once per-row files avoid partial append tails. A process dying before record publication leaves either no committed record or an observable staging file; reopen never silently truncates or removes it. After destination publication, the record is never deleted. If staging remains (a crash between link and unlink), reopen rejects the incomplete store without exposing coverage. If staging is absent and the full layout and records validate, reopen counts the record as executed, including failed generations. Neither case retroactively certifies an unacknowledged directory fsync. Ordinary exception cleanup removes only that invocation's staging name, whether or not its inode was already linked to the published destination. No operator repair helper is part of BS1. Failure injection tests must distinguish these stages and assert already published records remain unchanged. Holding a lock does not certify external gate claims or prevent malicious uncooperative writers; it excludes cooperating workers.

Tests may copy it and use synthetic non-input identity hashes labeled unverified; create successful and all-nine-failure result fixtures without a checkpoint.
