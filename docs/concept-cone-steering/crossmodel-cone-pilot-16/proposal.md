# Cross-model Concept Cone pilot V1 — execution contract

Status: exploratory V1, with Qwen and Gemma executed; this is not a replacement for the 200-company Qwen runs or C2 layer-localization experiment. Owner: `scripts/probe_concept_cone.py`. No cross-model steering or paper confirmation claims follow from running this alone. **Layer-source correction:** L15/L25/L19/L12 below came from the early 16-company C2 cross-entity run, not the later 427-company C2 v2 condition-flip run (L16/L27/L19/L14). Do not relabel V1 results as using 427-company-selected layers; changing layer source requires a new version.

## Numbered requirements

1. Population: `data/sp500_constituents_2020_2025.csv`, rows with `year=2024` and `index_name=S&P 500`: exactly 503 distinct tickers with company name and sector. Deterministically assign exactly 402 construction and 101 evaluation tickers with seed 20260923 (sort tickers then shuffle with `random.Random(seed)`); persist ticker lists, source CSV SHA-256, seed and split hash in the run metadata. The five historical tickers MO/CNC/FOXA/TSN/BAX, if used as a quick smoke, are not the formal result unless they belong to evaluation split. Never use evaluation companies to rank, choose, sign-align, sector-demean or fit a direction.
2. Run independently for the four completed models listed in `docs/concept-cone-steering/claim-to-evidence.md` C2: Qwen3.5-4B (L15), Gemma-4-12B (L25), GLM-4-9B (L19), GPT-OSS-20B (L12). Each model must calculate its own clean buy-minus-sell log-probability margin on the same frozen balanced prompt for every construction company; select its Top 20 and Bottom 20 from its 402 construction members only (ties by ticker). Do not reuse the Qwen 200-company ranking. Persist compact per-company ranking, no raw states. Check model identity, tokenizer, exact prompt/hash, selected layer, model checkpoint and git provenance. For GPT-OSS preserve native packed model weights (`dtype="native"`). Fail closed on incompatible models, missing tokenizer continuation tokens, nonfinite scores, offload, OOM or malformed spans; do not silently skip companies.
3. Fit the existing sector-demeaned token-wise 4D contrastive SVD on each model's own top/bottom 20 at its own instruction-peak layer; sign-align against the contrast mean and inject the normalized centroid at that same layer. Variable-length token spans must be aligned by the exact common instruction suffix and validated across construction and evaluation: use only the maximum common suffix present across *all* evaluation prompts (no silent truncation of unmatched tokens). Record effective token count and per-token centroid norms. For scoring use actual fixed decision prefix and correct one-token buy/sell continuation; greedy generation from prompt without prefix is separate, with parse failure reported separately. Keep legacy 200-company invocation/output unchanged if possible; introduce an explicit full-population CLI mode for V1.
4. Alpha grid frozen for this exploratory run: 0, 2, 3, 4, 5, 6; balanced prompt; 4D centroid; no per-target alpha tuning. Generate greedily up to 192 new tokens (pilot at 48 truncated every JSON); strict JSON parse, never infer a valid decision from partial JSON. Evaluate each of the 101 held-out companies per model at all six alphas, capturing compact margin, generated buy/sell/unparsed, parse status, flip vs its own alpha 0 (when both parse), and model/target/alpha metadata. Preserve generated text only if bounded; never store raw residuals, activations, gradients or caches. Compare raw alpha only within the same model; report norm if comparing models. User-facing table: alpha as columns, model × ticker as rows (one margin and decision per cell); include aggregate decision/parse/flip rates with denominators, and make it clear 101/503 companies were evaluated.
5. Perform a small smoke first (five historical tickers allowed, label it non-confirmatory), then execute model runs separately with unique output paths, validated metadata and resumability/restart safety. Full GPU runs are integration, not deterministic tests. Do not modify original `note.md`, `claim-to-evidence.md` historical results, dirty `docs/research-scripts.md`, or untracked `scripts/probe_operator_comparison.py`.

## Implementation slices and acceptance

- **Slice A — preparation/evaluation implementation:** edit `scripts/probe_concept_cone.py`, add `tests/test_probe_concept_cone.py`; optional small helper in same script. Unit tests with fake tokenizer/model or monkeypatch verify 503 split reproducibility/disjointness, model-specific rankings, dynamic span invariants, correct scoring-prefix call, failure cases, and alpha-column rendering; preserve legacy CLI defaults. No GPU required for tests. Run `uv run pytest -q tests/test_probe_concept_cone.py` and `uv run python -m compileall -q scripts/probe_concept_cone.py`.
- **Slice B — smoke and run:** after reviewing slice A, run a short integration smoke on available GPU and then production runs one model at a time, writing only under `artifacts/<model-slug>/concept-cone-steering/runs/crossmodel-v1-*/`. Confirm counts, provenance and alpha columns before summarizing in the response. If model-specific support fails, record failure explicitly rather than inventing results.

## Interpretation limits

A 402/101 fixed split does **not** evaluate all 503 companies. The five historical tickers were chosen using earlier Qwen observations and cannot be treated as unbiased held-out evidence. C2 model-specific layer peaks come from a different experiment and were not selected prospectively for this cone study. No random-direction controls, independent splits, multiple seeds or matched-norm dose comparison are part of this narrow pilot; do not claim generalization, C3/C8/C10 confirmation, or behavior change from margin alone. Report actual greedy decision and parse status separately.
