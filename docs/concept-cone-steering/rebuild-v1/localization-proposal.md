## Two fixed pair families answer different questions

The pairing algorithm does not search for a company or evidence contrast with a large effect. Every approved ticker/condition/trial has one target in each family. A planned pair exists even when its clean decisions agree; agreement is a retention/reason diagnostic, not a toward-source-flip denominator.

1. **Cross-company, same evidence:** within each issuer role, sort issuer IDs by `(sha256_json({'seed':20261002,'role':role,'issuer_id':issuer}), issuer_id)`; for every target issuer take the next issuer cyclically as donor. Choose the lexicographically smallest registered ticker of that donor issuer. Keep target condition/trial. This is role-preserving and issuer-disjoint; target share classes remain separate planned rows with company-first weighting. Donor selection is independent of generated buy/sell, sector and historical rankings. All four conditions remain present even when unanimous and opposite-clean denominator is zero. Within-role donor reuse is visible and no fitting uses these donor tensors as an upstream method anchor.
2. **Same company, different evidence:** use fixed reciprocal condition pairs `++ ↔ --` and `+- ↔ -+`, unchanged ticker/trial. The first is a two-item polarity/content contrast; the second is the exact P1/N1 order reversal. Report these separately, never merge them into a preference-transfer curve or call the two-item polarity contrast a pure order test.

The complete table has503 ×4 ×2 =4024 pair rows: fit2416, validation600, calibration208, evaluation800. Pair identity binds both parent row keys, role, family, contrast name and algorithm version. Selection flags label valid opposite-clean vs same-clean vs invalid-parent outcomes without discarding rows; the current GLM parent has no invalid rows. Baseline decisions define denominators after the fixed pairs are constructed, never donor choices.

## Prompt positions remain auditable when lengths differ

For every pair, render both original prompts with the parent's exact wrapper, tokenizer/schema, precision, cache=true and512-token/180s policy. Capture only original prompt residuals; no generated answer-prefix donor and no activation export.

Primary residual site is **post-block**, all model layers (`0..len(model.layers)-1`), not a historical peak. Whole entity/evidence1/evidence2/instruction span replacements are the four primary position arms. Identical span token tuples use exact ordinal mapping; otherwise explicitly named relative_rank transport maps target ordinal j to floor((2j+1)D/(2T)). This is positional transport, not semantic token equivalence. Cross-company shared evidence/instruction should use exact mapping where boundary tokenization permits; any fallback is recorded, never hidden. Same-company changing evidence may require relative transport. Tail-overlap mapping is an entity-alignment sensitivity arm. Mapping policies/absolute positions/full and selected token counts are saved before execution.

Secondary position arms are first/middle/last single token and tail4 in each span. Tail4 changes min(4,T) target tokens; report the actual count and do not claim exact matched-count equivalence for shorter spans. Every arm records actual induced delta norms, relative norms and selected-token opportunities. Full-span effects are not interpreted as intrinsic span importance solely from larger edits. Additional norm-matched controls require their own execution contract; they are not implicitly completed by recording norm.

## Development chooses candidate layers without forcing the original hypothesis

Fit and validation provide the full-layer discovery/replication maps; calibration is reserved for later dose work and does not select sites. Evaluation replacement at frozen selected candidates is a later phase, not a data source for site selection. Candidate ranking uses whole-span generated toward-source ITT, company-first within target ticker then issuer-cluster paired bootstrap; invalid interventions count no flip. Same-clean pairs report decision retention and reason changes separately. No opposite-clean pairs ⇒ NA, not0% and not a margin-created denominator.

Before dispatch, the runner contract must fix the site-ranking tie order, candidate count/band rule and held-out multiplicity policy. Those choices are deliberately not delegated to an implementation agent or inferred from evaluation labels. A selected replacement peak supplies a candidate for DIM/cone only; it does not establish the best additive steering layer. None of neuron discovery, DIM fitting or cone initialization is conditioned to force geometric agreement with A.
